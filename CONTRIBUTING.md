# Contributing

The published `imcc-sf04-v1.0.2` datapack is immutable. Do not edit its JSON
in place. A new complex or coefficient is a new pack version and must update
the manifest/hash, regenerate affected goldens, and add a changelog entry in
the same commit. A JSON edit that changes the published canonical payload under
the old version fails `load_datapack()`; whitespace or key-order-only edits can
still load, but any raw-byte edit must also update the manifest/hash. The loader
requires exactly 38 published-core rows and the frozen canonical hash.

## Proposing a datapack row

Include the balanced parent-oxide stoichiometry, `A` and `B`, declared
temperature domain and basis, reaction/reference-state description, and a
public source citation with table/page or equivalent locator. Use a source
independent of the fit being checked: a model workbook or output generated by
the same coefficients is not an independent validation reference. Do not
retune a row to match a bench, workbook, or another engine.

The loader's provenance rule is narrow and explicit. `provenance_class` is
optional metadata on published base rows; `load_datapack()` does not enforce a
particular base-row value. S/P extension rows must use
`extension-compound-thermo`, `tier: EXT-SP`, `certification: denied`, and a
non-empty provenance `source` and `table_id`. The loader does not resolve URLs,
rebalance reactions, or validate prose metadata. Research counterfactuals use
the labelled in-memory path `label_research_datapack()`, not an edited JSON
published pack.

Keep sources and metadata public and repository-relative. Do not include
private filesystem paths, private workbook copies, or generated local paths.

Run the local gates before proposing a change:

```bash
scripts/ci-local.sh
# or, for the current interpreter only:
scripts/ci-local.sh --quick
```
